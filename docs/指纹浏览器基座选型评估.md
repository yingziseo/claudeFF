# 指纹浏览器基座选型评估

2026-10-12，北京时间。范围为用户实际使用的 Windows/macOS 桌面浏览器，不把自动化 SDK、内核二进制和完整管理客户端混为一谈。数字来自当日 GitHub API，后续会变化。

## 结论

当前首选 **Donut Browser 完整客户端**，主要备选 **CloakBrowser Manager**。这是源码、发行和维护情况的适配评估，尚未完成这两个原版客户端的 Windows 对比实测；不能声称 Donut 已经是稳定性或指纹效果最好的项目，也没有完成本仓库的基座迁移。

用户要求复用持续维护的完整产品代码，不继续只接内核再自行拼出管理层。按测试项目、可用性优先推进，保留原始来源说明，不因未来售卖的假设停止当前测试；本次没有购买付费服务或实施商业发布。

## 已阅读的源码与实际限制

- Donut 调研 checkout：`62e37c884db9b1a08c303c3dbdefa23134966d1a`；稳定版 v0.33.0 对应 `89ddeb05bff74847d825629f69063f1185cb3a49`。已读 `src-tauri/src/browser_runner.rs`、`browser.rs`、`profile/`、`proxy_manager.rs`、`ip_utils.rs`、Tauri 配置及发行工作流。实施优先锁定稳定发行，不直接跟随每天的依赖更新。
- Cloak Manager 调研 checkout：`eee343ea1ed2e6219b3a2a9d23cf47284f776620`。已读 `backend/browser_manager.py`、依赖、PyInstaller 配置、README 与发行记录；持久 context、会话恢复、重复启动与档案操作锁已有实现。
- 两个完整源码只读取到临时目录，未安装依赖、未在服务器编译或启动。未把调研 checkout 冒充已集成产品。

本仓库 V3 的 `internal/browser/browser.go` 将运行期间检测站失败与出口变化混在一起，直接 Stop；启动强制浏览器出口与一次全局观测相等。`internal/code/manager.go` 存在同类相等门槛。检测接口故障或网关出口策略可能让有效代理被拒绝。这是源码确认的设计问题；用户秒退出的全部实机原因仍待日志和复现验证，不能断言仅有一个原因。

Donut 的 IP 检查已有多个免费纯 IP 端点及总超时，地区查询与代理可用结果分开，符合本次简化方向。环境/代理生命周期已有更完整的功能与分工，这是源码范围判断，不是实测性能排名。

候选也存在未解决报告：Donut [白屏 #653](https://github.com/zhom/donutbrowser/issues/653)、Cloak Manager [自行退出后的驱动回收 #54](https://github.com/CloakHQ/CloakBrowser-Manager/issues/54)。尚未独立复现，应进入验收，不把单个 issue 当普遍失效的证明。两者原版均可能在线准备内核，必须在云端预装本项目所需内核和基础资源，保留完整 ZIP 要求。

## 原版验收后再裁剪

在 GitHub Windows 运行器先验证原版正式包及其原始源码构建，再修改品牌和业务。记录真实结果、版本、协议和进程退出原因。

1. 正常原生窗口持续运行至少 15 分钟；开关新标签、关闭信息页、保留官网会话不因探针超时退出。
2. 反复启动/停止至少 10 次；用户正常关闭、应用退出与异常结束分别核对，避免残留锁与错误进程回收。
3. 同一持久环境保存 Cookie、localStorage、历史、书签和实际对话 URL；重开正常恢复。密码填充与真实 Claude 授权未验证时单列。
4. HTTP/SOCKS5 认证代理走实际管理端到内核路径；免费接口返回真实出口。地区查询失败显示未知；429/503 与代理认证/连接错误分开，不回退公网直连。查询 IP 成功不等于 Claude 登录成功。
5. 原版可用后裁剪单账号、唯一全局代理和官方原生 Code，复用 profile/内核/进程模块，跟踪来源和本地改动。macOS 两架构分别验收。

以上候选实测尚未运行，没有产生新 ZIP。原 V3 云测是当时有限证据，不能抵消用户新故障。
