# claudeFF 开发项目计划：单账号 Claude 工作空间

版本：V2 · 2026-10-10。本文是当前需求基线，替代旧多环境指纹浏览器 MVP 计划。历史变更只供追溯，不再作为开发指令。其他文档不得覆盖本文的产品范围；用户后续明确要求优先，并同步修订所有相关文档。

当前状态：新版单账号界面、Windows 核心、WSL2 安装与整进程隔离代码，以及后期授权服务/管理面板已实现。核心模块、实际 Linux 隔离/官方 Code 安装、实际 Windows 指纹内核、Windows 构建和前端云测已有通过证据。用户取消前端确认门槛并授权整体开发，最后集中优化界面；实际 Windows/WSL2 体验由用户之后进行。逐项状态以 [开发进度与验证报告](开发进度与验证报告.md) 为准，本文仍保留全部验收要求。

## 1. 产品定位与范围

面向 Windows 11 x64 的单人、单 Claude 账号工作空间。围绕一个稳定环境配置、一份全局代理，提供三个产品入口：

| 入口 | 本期要求 |
| --- | --- |
| Claude.ai 网页端 | 首期核心：真实独立指纹 Chromium 浏览器，正常浏览、持久登录与浏览数据 |
| Claude Code 终端 | 首期核心：一键准备 WSL2 强隔离环境、安装官方 Code、同步适用环境参数并启动终端 |
| Claude 桌面客户端 | 仅预留入口，显示“正在开发中”；不下载、不启动、不实现桌面客户端集成 |

这里的“单账号”指一个用户管理自己的 Claude 使用环境，不是后期授权服务只能有一个购买用户。产品授权账号、Claude.ai 登录和 Claude Code 官方授权是三种不同身份，不能混用或声称自动互相登录。

移除多环境列表、批量创建、环境搜索、无限环境数量和跨环境 IP 独占逻辑。一个配置可以同时供浏览器与 Code 使用，多个正常标签页也不受旧“一个 IP 只能一个窗口”规则限制。保留应用单实例及同一浏览器数据目录的进程锁，防止重复启动损坏数据。

不增加团队、云端浏览数据同步、支付、订单、套餐、远程浏览器、设备绑定或微服务。最后阶段仍有轻量卡密和用户管理面板，见第 9 节。

## 2. 全局代理：只配置一次

- 全局设置只保存一份当前代理：协议、主机、端口、可选用户名和密码。浏览器页和 Code 页只展示共用状态及跳转，不提供独立代理配置。
- 首期围绕用户购买的固定出口住宅代理；支持 HTTP、HTTPS、SOCKS5 上游及适用的用户名密码认证。协议能力分别实测，不把“保存成功”当“连通成功”。
- Claude Code 通过其原生 HTTP/HTTPS 代理机制运行，不修改 Code 源码、不要求插件。SOCKS5 上游经应用桥接转换为 HTTP 入口。
- 代理秘密使用 Windows 用户级安全存储；运行时注入必要连接配置。不得把真实上游密码写入项目 settings.json、启动脚本、命令行日志或仓库。Code 只获取专用隔离系统内的受限回环入口；上游密码留在 root 受管转发层，不传给 Code 用户。
- 应用级全局代理不等于修改 Windows 系统代理，不接管用户其他应用的网络。清理受管进程继承的冲突代理变量；防止大小写代理变量或 NO_PROXY 令业务请求绕过代理，必要的本地授权回调单独处理。
- 必须分别验证管理服务、实际 Chromium、实际 Code 隔离环境的网络路径；记录出口 IP、地址族、时间和检测版本。仅 HTTP 探针一致不能证明 Code 所有流量一致，还需验证其真实连接及子进程出站策略。
- 同一个代理网关可能轮换出口。两端实际出口不一致、代理失效或检测过期时，不显示“已一致”；阻止启动或中断受管访问，提示检查全局代理。不得自动直连或偷偷换代理。
- 改代理影响两端：提示影响范围，受控停止受影响进程、使旧检测失效、更新唯一配置、重新检测后再启动。禁止浏览器用新配置、Code 悄悄沿用旧配置。
- IP 地区、城市、延迟、住宅属性分开展示。地区未知显示未知，住宅属性无可靠证据显示“未验证”。不做无依据的 IP 安全评分。

## 3. 一份稳定的环境配置，两条进入路径

环境配置是持久化的唯一配置档案，不是多个账号的配置池。建议包含稳定标识、版本、创建来源、语言、时区、浏览器参数与内核版本、Code 隔离配置版本，以及全局代理引用。两端记录各自实际应用的版本，不能只依据数据库值宣布已同步。

### A. 先使用浏览器，再启用 Code

1. 配置并真实检测全局代理。
2. 创建稳定的浏览器环境配置与专用用户数据目录。
3. 启动真实浏览器，可自行登录 Claude.ai；登录行为由官网处理，本工具不采集 Claude 密码。
4. 点击安装 Code，自动沿用已存在的环境配置，无需再次填写代理。
5. 显示“正在下载安装，并同步浏览器环境配置，尽量保持环境和设备信息一致”。展开详情可查看实际步骤和同步结果。
6. 准备隔离沙箱 → 下载安装官方 Claude Code → 同步适用配置 → 核验出口与隔离策略 → 启动终端。任何步骤失败都停止，提供有针对性的重试。

已有浏览器环境是复用配置的依据，不以成功登录 Claude.ai 为安装硬门槛。不得从 Cookie 或界面猜测登录成功并标成已验证。Code 的官方登录可能仍需用户单独完成，浏览器 Cookie 不复制给 Code。

### B. 不使用网页端，单独启用 Code

1. 仍先配置同一份应用全局代理。
2. 没有本工具已有环境配置时，显示确认提示：

> 直接创建 Claude Code 环境，可能与该账号原有网页端的环境信息不同；若代理 IP 也不同，会增加环境差异。建议优先沿用原有浏览器环境，保持一致。

3. 提供“先配置浏览器环境”和“了解差异，继续设置 Code”。用户确认后生成唯一环境配置，再执行相同的强隔离安装流程。
4. 后续启用浏览器时复用该配置的适用字段，不随机生成第二套相互冲突的配置。

本工具不知道外部浏览器过去的真实指纹，不声称自动导入或还原。这个提示只说明环境差异，不宣称已证实封号概率显著增加；不在每个操作重复泛化免责声明。

## 4. Claude.ai 浏览器体验

- 实际采用开源指纹浏览器项目与 Chromium 内核。已采用 [adryfish/fingerprint-chromium](https://github.com/adryfish/fingerprint-chromium) 的 `148.0.7778.215` Windows x64 预编译版本；来源、固定校验值与源码对应关系见技术和来源文档。不是只引用项目名字或伪造 UI 参数。
- 不自行编译 Chromium。Wails WebView2 只承载管理界面，不冒充完整浏览器。Chromium 是 Chrome 的开源基础，不等于完整 Google Chrome 产品。
- 使用一个专用 Chromium 用户数据目录，与用户日常 Chrome 分开，保留 Cookie、会话、历史、书签、缓存、扩展兼容能力及浏览器支持的密码保存/自动填充。关闭后不清空登录数据。
- 目标是熟悉的 Chrome 标签页、地址栏、前进后退、下载等体验。Google 账号同步、专有组件和所有扩展的完全兼容不能预先承诺；选定内核后逐项验证，差异明确记录。
- 启动成功后默认打开两个标签页：本地环境信息启动页，以及 **https://claude.ai/**。将沟通中的 claude.al 统一为 claude.ai。
- 再次点击启动优先激活既有浏览器，避免重复打开窗口或破坏 profile；已运行时打开官网优先复用现有官网标签页。
- 启动页参考比特浏览器信息组织方式，原创布局：出口 IP、地区、连接状态、语言、时区、内核版本、环境标识、检测时间；提供刷新检测、复制 IP、查看指纹详情和官网入口。
- 启动页必须由受管 Chromium 真实打开，其显示值来自本实例的实际观测。未检测、失败、过期、未知与历史结果明确区分。
- 本地页面资源不对外暴露管理权限；CDP 和管理接口只开放必要本地访问并鉴权。普通网页不能利用本地端口任意操作主机。

### 高级设置中的指纹信息

展示配置值、实际观测值、支持状态与最近验证时间。主流程只展示必要项，高级设置可以查看：

| 类别 | 要求 |
| --- | --- |
| 版本与平台 | 真实内核版本、UA / UA-CH、操作系统信息；不能靠伪造版本替代兼容验证 |
| 地区 | 语言、Accept-Language、时区、地理位置策略；时区含夏令时，不能只固定 UTC 偏移 |
| 显示与硬件 | 分辨率、缩放比、CPU 并发数、内存、WebGL 信息；按内核支持情况实现 |
| 渲染 | Canvas、Audio、字体等内核提供的能力，稳定配置，不每次启动随机改变 |
| 网络与权限 | WebRTC、IPv4/IPv6、DNS 路径、定位/摄像头/麦克风权限状态 |
| 状态 | 已配置、已验证、待验证、暂不支持分别显示，不用统一绿色“安全”替代 |

不能把数据库里存了一串参数当成真实指纹已生效。高级变更必须先停止受影响进程、记录配置版本并复核；不默认提供一键随机重置身份。

## 5. Claude Code 强隔离与一键安装

用户已明确选择安全优先，接受 WSL2 和额外隔离组件的资源开销。**不提供原生 Windows 弱隔离替代，不允许沙箱失败后降级直跑。**

### 安装和启动状态

未安装 → 检查系统条件 → 准备专用 WSL2 环境 → 下载安装官方 Code → 同步配置 → 验证隔离及出口 → 待官方授权（如需要）→ 可用/运行中。支持失败、取消、重试、等待提权、等待重启，已完成的可信步骤可恢复，不伪造进度百分比。

- 检查 WSL2、虚拟化、可用磁盘和依赖。启用系统组件、提权、重启的实际影响在执行前说明；“一键”不等于跳过操作系统确认。
- 独立受管发行版和非 root 运行用户；不修改、删除用户已有 WSL 发行版，不默认关闭其他发行版，不覆盖全局 `.wslconfig`。
- Code 通过官方分发渠道安装；记录版本、来源与完整性验证方式。下载和更新也按全局代理策略执行。安装失败留可恢复状态，不删除项目数据。
- 终端提供正常输入输出、窗口尺寸变化、Ctrl+C、退出状态、重新打开和授权提示。选择项目目录后只开放该项目及必要依赖，不默认开放整块磁盘。
- 默认限制 Windows 磁盘自动挂载、宿主进程互操作、宿主 PATH 继承与无关设备访问。只关闭自动挂载不等于已实现强隔离，必须有权限和进程边界验证。
- WSL2 是运行基础，仍需覆盖整个 Code 进程及其子进程、文件工具、MCP、hooks 的文件和网络限制；不能仅开启官方 Bash sandbox 就声称完成。
- 权限最小化，禁止受管 Code 用户取得 root 或自行改写网络限制；系统级出站限制只允许必要转发路径。子进程即使清除代理变量也不得直连，涵盖 DNS、IPv6、UDP 和重连。
- 当前采用隔离系统内 root 回环转发，配置由受管 wsl.exe 标准输入传入，不开放 Windows 与 WSL 间的 TCP 代理端口。未来若引入跨系统网络通道，须独立鉴权和限范围访问，不能监听全部网卡暴露代理。
- 隔离失败、出口不一致或策略未生效时禁止进入可用状态；必要的登录回调也应走受限通道，不能为完成 OAuth 全面开放宿主互操作。

### 共享与不能等同的部分

浏览器与 Code 共用全局出口、语言、时区和稳定配置来源。Code 使用隔离系统自己的实际平台信息；WSL2 Linux 不能伪装成与 Windows 浏览器相同的操作系统内核。

Canvas、WebGL、浏览器 UA 等不复制给 CLI 当作“相同指纹”。修改 LANG/TZ 或独立目录不足以隐藏所有系统信息。应分别显示“已同步的适用字段”“浏览器专属字段”“实际系统差异”。目标是减少非必要暴露、保持适用配置一致，并用实测证明隔离，不是宣称所有设备信息完全相同。

## 6. 界面与素材

采用接近苹果原生应用的简约交互，保持 Windows 窗口习惯；默认深色并完整支持浅色。新首页围绕三个产品入口与一份全局连接状态，不再沿用多环境后台表格。

- Claude.ai 与 Code 为主要可用入口；桌面版显示“正在开发中”，不伪造安装进度。
- 项目和产品位置按用户最新要求使用 Claude 官方图标，普通操作使用 Lucide 等统一主流图标库。旧生成图标停用；素材来源和使用边界见品牌文档。
- 高级设置默认收起，必须能查看指纹详情。安装进度和一致性结果有详细信息，但新手主操作保持清晰。
- 前期产品登录/注册保留为纯前端交互，随意输入即可进入，不联网验证；与 Claude 官网/Code 官方登录明确区分。
- 网页预览明确标记示例，不在用户普通浏览器里打开官网后宣称已走受管代理。
- 保留第三方工具身份说明，不暗示官方出品。防封是用户使用目标，不作为绝对保证或无实测依据的成功率指标。

## 7. 存储、恢复和资源边界

SQLite 保存唯一环境配置、全局代理非秘密字段与秘密引用、应用设置、安装阶段、检测记录和两端配置版本；最终授权记录到最后阶段再实现。Windows 用户级安全存储保护秘密，Chromium 和 Code 各自保留官方登录材料，不互相拷贝认证信息。

浏览器 profile、WSL 数据和用户项目分开管理；更新程序不能覆盖它们。数据库迁移失败要能恢复；日志脱敏，不记录完整代理 URL、令牌、Cookie 或终端秘密。导出诊断必须先脱敏。

删除、重置环境、卸载受管发行版或清理数据均说明范围并确认；清缓存保留 Cookie/密码/配置。运行中修改配置须有受控停机。应用退出时有任务运行，应提示并受控关闭，避免丢失终端任务；不自动杀死用户其他 WSL 进程。

WSL2、内核和项目工具会增加体积与内存，不承诺整个产品“零依赖、极小安装包”。限制受管进程资源并实测，不为了限额改动用户所有 WSL 实例的全局配置。

## 8. 实施顺序与验收

1. 当前先统一全部需求文档与协作规则。
2. 重做前端：三入口、全局代理、浏览器启动页、指纹高级设置、两种 Code 进入路径和强隔离安装进度；云端构建后提供网页链接。不再等待逐项风格确认，整体后集中优化。
3. 后端技术验证：开源内核选型、全局转发、真实浏览器出口、WSL2 整进程隔离及转发可达性。未验证能力不能写成已实现。
4. 实现浏览器、共享配置、持久化与完整 Code 安装/终端流程；逐步连接真实 UI。
5. 完成核心验收后，最后加入授权与管理面板。
6. Windows 实机验收、恢复测试、发布可运行 ZIP、源代码、运行说明与验证报告。

| 验收项 | 必要证据 |
| --- | --- |
| 前端 | 三入口、登录开发态、全局代理唯一入口、两条 Code 流程、高级指纹、明暗主题、键盘与窄屏；云端截图及用户风格认可 |
| 共享配置 | 浏览器先建/Code 先建都只生成一份配置；后启用另一端复用；修改后版本一致且重验 |
| 浏览器 | Windows 上启动真实内核，两个默认标签页，实际参数、密码保存、历史、书签、Cookie 重启保留；不污染日常 Chrome |
| 全局代理 | HTTP/HTTPS/SOCKS5 与认证实测；两端共用出口，改代理同步失效；代理失败、IPv6/DNS/UDP、轮换出口和子进程绕过尝试验证 |
| Code 安装 | WSL2 缺失、虚拟化关闭、重启、下载失败、取消/重试、已有环境复用、官方授权及真实终端可用 |
| 强隔离 | 未授权宿主目录、宿主进程、提权和非代理网络访问被拒绝；Code 整进程及子进程覆盖；失败无弱隔离回退 |
| 恢复 | 应用多开、异常退出、代理中断、更新/迁移、WSL 残留、项目和浏览数据不丢失 |
| 构建 | GitHub Actions Windows 构建 ZIP；云端浏览器测试不替代 Windows/WSL 实机证据 |
| 授权（最后） | 真实登录/激活/撤销/重复激活/离线边界、后台、开发入口关闭 |

所有构建、安装项目依赖、类型检查、编译测试和浏览器测试只在 GitHub Actions。当前服务器仅编辑、轻量检查和 Git。云端环境无法验证 WSL2 或桌面交互时，明确要求可用 Windows 验证环境，不能把未运行项目标成通过。

## 9. 最后阶段商业授权与交付

核心包括浏览器和 Code，两者测试通过后才加入永久联网卡密、真实产品账号和轻量“卡密和用户管理面板”。后台管理卡密、激活用户、用户信息、授权状态、最近在线时间与必要使用状态。在线由心跳推算，展示最近上报时间；不上传 Claude 对话、代码、浏览记录、Cookie 或代理秘密。

正式产品账号密码安全哈希，保持登录使用受保护会话；开发跳过入口必须关闭。永久授权不代表永不复核撤销；重复激活、换机/恢复、心跳和离线宽限在该阶段集中确认，不自行增加硬件绑定、付费等级、支付或订单。

交付已编译 Windows 免安装 ZIP；额外 WSL2/运行依赖通过受管流程准备，不能把源码 ZIP 当可运行程序。本开发版内核按需下载并固定摘要校验，ZIP 不捆绑 Chromium 或 Ubuntu 镜像。授权服务保持单服务和简单数据库；当前使用高熵卡密及服务端摘要核验，未引入客户端签发密钥。测试报告区分已验证、未验证、部分实现和未实现。
