# 0.1.0 实现与验证边界

本文件描述当前代码，不是 Windows 验收结论。

## 一体化操作

只有一个用户入口 `ClaudePrivacy.exe`，在同一窗口“开启防护 → 验证防护 → 导出结果”。Probe、Relay 是内部组件。验证代码与配置代码分开；验证不直接采信主界面的成功标志。

## 清单生成

读取实际应用的恢复记录，仅构造已启用规则的检查：

- 专属沙箱是否接管本次探针（宿主通过 SbieApi 查询运行时 PID）。
- 已启用的浏览器/私人目录能否从沙箱列举；只表示列举访问路径，不能推断其他路径全部不可读。
- 工具测试文件、测试注册表键与已发现并限制的浏览器偏好键的实际拒绝行为。
- 仅 TCP 接管模式：SOCKS 桥接回显随机挑战、沙箱出口请求。
- 仅曾由工具关闭并读回确认的模型改进开关：再次读回。

没有语言、硬件、全面遥测、UDP、DNS、IPv6 等虚构检查，也不将用户的 Claude 使用测试混入防护验证。新报告运行前清空旧结果。

## 限制与待验证点

1. 未在本 Linux 主机运行 Windows 原生程序，尚未验证 Sandboxie 版本/证书、驱动、配置权限、WPF 绘制、Claude 登录和更新。
2. 标准沙箱不是默认拒绝所有读取；本版仅增加明确路径的拒绝规则。文件句柄、外部服务、进程间通信和路径别名不能由这些样本穷尽证明。
3. 本地探针面向诊断，不是抵抗恶意本地管理员篡改的远程证明系统。
4. 本版不拦截全部遥测、不透明解密 TLS、不捕获 Claude 全部文件/API 行为。审计记录为本次验证访问证据及配置变更恢复记录。
5. TCP 桥接不提供 UDP、DNS 或全系统路由；依赖 Sandboxie Winsock 支持。IPv4 本地代理不能作为 IPv6 兼容保证。当前没有内核级强制断线阻断。
6. 模型改进偏好依赖可访问的 UI Automation TogglePattern 及已确认的英文设置名称；其他界面/语言不猜测操作。读回仅证明界面状态，不独立证明服务端数据处理。
7. 没有自动强制普通快捷方式入箱；启动按钮会拒绝向现有沙箱外同名进程转交。
8. 恢复之前要求专属沙箱无运行进程。恢复时保留外部配置变更，保留沙箱文件，不删除用户会话。

## Windows 复核步骤

先在空测试目录和自建文件上开启规则，分别跑开启前、开启后、恢复后的探针检查；仅开启后应得到目标拒绝结果。再测试一个已存在的浏览器档案目录，并确认浏览器自身在沙箱外仍可正常使用。

分别测试没有 Sandboxie、服务停止、目录不存在、配置外部改动、上游代理拒绝认证、上游断开、工具窗口关闭后代理存活、系统重启后旧代理失效、Privacy 页面不可见、开关恢复等情形。失败或未知必须不显示通过。

你随后安装 Claude，通过专用启动按钮做正常使用检查。若有异常，导出当前报告并记录 Windows、Sandboxie、Claude 版本与触发动作。只凭本地检测通过不能宣布 Claude 功能验收完成。
