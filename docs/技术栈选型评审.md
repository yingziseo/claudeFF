# claudeFF 技术栈与技术方案评审

更新时间：2026-10-10。结论状态：推荐方案，正在与用户沟通；尚未初始化业务代码或执行构建。

## 结论

最符合当前需求的组合仍然是 **Go + Wails 2 + React/TypeScript + SQLite + 独立 Chromium**。保留原计划主技术栈，调整开发阶段、构建位置及后期授权范围。

“更轻”需要同时考虑管理客户端额外开销、实际浏览器进程开销、发布体积、开发复杂度和维护成本，不仅比较框架宣传的安装包大小。项目资源占用需要在实际构建和真实环境测试后报告，不提前承诺具体内存或包体数字。

## 桌面方案比较

| 方案 | 与本项目的关系 | 建议 |
| --- | --- | --- |
| Go + Wails 2 + React | Go 处理进程、代理和本地存储；React 负责高质量界面；Windows 管理界面使用系统 WebView2，实际环境仍是独立 Chromium | 首选，沿用原技术栈 |
| Electron + React | 可以实现精致界面，但管理端还要携带 Electron 的 Chromium 和 Node.js 运行时；项目本身另需独立指纹 Chromium | 不必引入额外运行时 |
| C# + WPF / WinUI 3 | Windows 原生整合便利，可以实现需求；但会替换原 Go 技术体系，桌面 UI 和后期 React 管理面板使用不同界面技术 | 有原生桌面或现成 C# 团队优势时再考虑 |
| Rust + Tauri | 用户原计划明确不使用 Rust 和 Tauri | 不纳入当前实施选择 |

上述为针对本项目需求的取舍，不是对各框架性能的统一排名。精致和可信的界面主要依赖设计、状态处理与细节实现，框架不能自动保证 UI 质量。

## 推荐的模块技术栈

| 模块 | 推荐技术 | 取舍 |
| --- | --- | --- |
| Windows 桌面外壳 | Wails 2 稳定发布版 | 不为了新版本追逐 Wails 3 测试版；锁定经过云端验证的版本 |
| 本地业务 | Go | 同一进程管理环境、代理、进程和存储，尽量使用标准库 |
| 客户端 UI | React + TypeScript + Vite | 构建后资源嵌入程序，用户不需要安装 Node.js，也不运行 Vite 服务 |
| UI 样式与控件 | Tailwind CSS + 按需引入的 shadcn/ui + Lucide | 使用统一设计令牌，按需选择控件，不堆叠多套大型组件库 |
| 前端状态 | React 本地状态与小范围 Context | 先不用 Redux 等全局状态框架，遇到实际复杂度再评估 |
| 本地数据库 | SQLite + database/sql | 表和查询清晰，不为了少量本地数据引入大型 ORM |
| SQLite 驱动 | 优先 modernc.org/sqlite | 纯 Go 减少 Windows CGO 工具链复杂度；构建开销与产物大小在云端实测 |
| 浏览器内核 | 预编译的 fingerprint-chromium Windows 内核 | 核验版本、来源与能力；不自行编译 Chromium |
| 浏览器生命周期 | Go os/exec + Windows 进程管理 | 控制完整进程树和退出，识别用户手工关闭与异常退出 |
| 浏览器控制 | 单一 CDP 库，优先 chromedp | 用于实际浏览器网络复核和支持的环境参数；不同时引入多套浏览器控制库 |
| 代理检测与桥接 | Go net/http、net、crypto/tls、golang.org/x/net/proxy | 支持 HTTP、HTTPS、SOCKS5 及认证；协议分别做真实测试 |
| Windows 秘密存储 | 用户级 DPAPI | 保护代理秘密和会话材料；不意味着浏览器全部用户数据均已加密 |
| 最后阶段授权服务 | 单个 Go HTTP 服务 + SQLite | 用于授权与用户记录，单实例起步；无需微服务、Redis 或 Kubernetes |
| 最后阶段管理面板 | React + TypeScript + Vite，复用设计令牌 | 管理卡密和用户；不要求重用整个桌面页面结构 |
| 构建与验证 | GitHub Actions | 所有编译性操作在云端，Windows 桌面程序在 Windows 运行器生成 |
| 客户端交付 | 已编译 Windows 免安装 ZIP | 解压运行，源码单独交付；不强制制作安装程序 |

实际依赖版本在工程初始化时从官方发布确认并锁定，提交 Go 与 npm 锁文件。不使用未验证的“最新”浮动版本作为发行依据。

## 最简客户端结构

```text
React 管理界面
       │ Wails 绑定与事件
       ▼
Go 本地业务进程
       ├── SQLite / 设置 / Windows 秘密存储
       ├── 环境状态 / IP 独占 / 故障恢复
       ├── 本地认证代理桥接 ──► 用户指定的上游代理
       └── 独立 Chromium 进程与环境数据目录
```

- Wails 只显示管理页面，不承担实际浏览器环境。
- 每个环境一个独立浏览器根进程与独立用户数据目录；Chromium 自身会创建子进程，不能把“一个环境”错误解释为整个浏览器只有一个操作系统进程。
- 客户端不另外启动通用 Web 后端或 Node.js 服务。必要的本地代理和环境首页只绑定回环地址。
- 用户使用的浏览器数据不发送到后期授权服务器。

## 主要流程与资源控制

1. 前期开发登录直接进入界面；正式授权最后接入。
2. 创建环境先真实检测代理，再生成稳定配置并保存。
3. 启动时重新检测、原子预占出口 IP、建立代理链路、启动独立 Chromium，并通过该实例复核网络。
4. 只有复核成功才将环境标记为可用；失败回收进程、连接和 IP 占用。
5. 关闭后保留数据，回收完整运行资源。异常退出和多开客户端不能绕过互斥。

按需启动浏览器；用户未打开的环境只保存数据。检测、事件和进程管理避免无意义的高频轮询。监测频率与故障处理应以实际可靠性测试确定，不用降低代理保护要求换取虚假性能数字。

固定出口代理优先、出口变更时停止环境，以及关闭管理程序时确认并关闭环境，都是当前建议，尚未作为用户最终选定的规则。

## 免安装 ZIP 的实际边界

- ZIP 包中应有 `claudeFF.exe`、运行说明、必要的内核资源及第三方许可材料；浏览器内核是随包提供还是首次选择，仍需最终确定。
- Windows 管理界面需要 WebView2 Runtime。多数 Windows 11 安装包含它，但发行仍必须检查缺失情况并提供官方安装指引，不能承诺任意 Windows 机器无依赖运行。
- 用户数据放 Windows 标准应用数据目录，避免覆盖程序目录时删除账号、设置与浏览器环境。
- 免安装不等于加密保护，也不决定卡密是否安全；普通用户应收到已编译程序，不需要本地编译源码。

## 最后阶段：联网授权与卡密和用户管理面板

- 在核心浏览器及中文客户端通过验收后，再开发真实账号、永久卡密、激活记录、撤销和状态复核。
- 面板展示卡密与用户的对应关系、激活状态、最近在线时间和明确范围内的使用概况。
- 服务器管理授权状态；签名授权材料可用 Ed25519，私钥只在签发端保存。客户端验证公钥不会赋予签发能力。
- 不承诺防破解。联网激活能管理正常客户端的使用与卡密生命周期；修改客户端仍可能绕过本地功能的限制，不能靠混淆或一次联网校验彻底解决。
- 在线心跳、离线宽限、重复激活及账号恢复策略在该阶段前确定；不提前实现设备绑定、付费套餐或订单支付。
- 管理端必须有真实管理员认证、HTTPS、权限检查、敏感数据脱敏和关键操作记录；开发跳过登录不应用于生产后台。

## 原规划需要调整的地方

1. **保持主技术栈**，不改成 Electron，也不推翻 Go 后端。
2. **UI/UX 提前**，第一阶段建立规范与注册登录交互，后续逐项连接真实业务。
3. **卡密与用户管理后台最后开发**，不在基础浏览器阶段创建授权服务器。
4. **构建全部云端化**，不在弱配置服务器安装项目依赖并编译，不使用本地热更新流程。
5. **补齐正确性边界**，包括代理断线、IP 变化、并发启动、进程树退出、数据迁移和开发登录发布检查。
