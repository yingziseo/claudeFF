# 技术栈与实现边界

版本：V2 · 2026-10-10。需求以 [开发项目计划](claudeFF开发项目计划.md) 为准。本文替代旧多环境方案，描述实施方向与待验证项，不是已完成功能报告。

## 技术方向

保留 Go + Wails 2 + React/TypeScript + SQLite。增加用户已明确选择的专用 WSL2 强隔离运行环境。轻量化仅适用于管理程序，不能以降低隔离要求换取小包体；不提供原生 Windows Code 弱隔离模式。

| 模块 | 方案与状态 |
| --- | --- |
| 管理界面 | React + TypeScript + Vite，Tailwind、Radix、Lucide；已有旧版原型，需重做 |
| Windows 外壳 | Wails 2 / 系统 WebView2；后端阶段实现，不用 WebView 冒充浏览器 |
| 本地业务 | Go 单进程管理唯一环境配置、全局代理、浏览器和 Code 生命周期 |
| 数据 | SQLite / database/sql，优先评估 modernc.org/sqlite；单配置而非多账号环境池 |
| 秘密 | Windows 用户级 DPAPI；受管转发层保存上游凭据，日志脱敏 |
| 指纹浏览器 | 预编译 fingerprint-chromium Windows x64，独立 profile；版本与兼容性需验证 |
| 浏览器控制 | Go 进程管理与单一 CDP 库（优先 chromedp），验证真实参数和出口 |
| 全局转发 | Go HTTP CONNECT / HTTPS / SOCKS5 上游适配；两端共用，不做两份设置 |
| Code 运行 | 官方 Linux Claude Code，专用 WSL2 发行版与整进程隔离限制；实现待验证 |
| 隔离组件候选 | Linux 权限/命名空间/网络限制；评估 anthropics/sandbox-runtime，不能只开 Bash sandbox |
| 终端 | 受管 Linux PTY 经应用桥接到前端终端组件；优先评估 xterm.js，尚未引入依赖 |
| 最后授权 | 单 Go HTTP 服务 + SQLite + React 卡密和用户管理面板 |
| 验证与发行 | GitHub Actions 云端；Windows ZIP 与 Windows/WSL 实测分别验收 |

不切换 Electron/Rust/Tauri，不引入 Redis、Kubernetes、通用 Node 后端或微服务。

## 运行结构

```text
Windows 管理界面（Wails + React）
          │
          Go：唯一环境配置 + 单一全局代理 + 秘密存储
          ├─ Windows 指纹 Chromium ──────┐
          │   专用 profile / 两个启动页  │
          └─ 专用 WSL2                  ├─ 受管转发通道 → 同一上游住宅代理
              整进程隔离 → Code + PTY ──┘
              仅开放所选项目与必要依赖
```

本图是目标架构，不代表已存在可用代理服务或沙箱。浏览器与 Code 可以同时运行，共享出口；应用单实例锁和 profile 锁只避免重复控制与数据损坏，不实行旧跨环境 IP 独占。

## 指纹内核选型

已调研 [fingerprint-chromium](https://github.com/adryfish/fingerprint-chromium)，基于 Ungoogled Chromium，提供 Windows x64 ZIP。2026-10-10 查询发布页可见 `150.0.7871.186`，仅为调研记录，不直接锁为产品依赖。仓库 LICENSE 标示 BSD-3-Clause；实际发行还需核对所选发布的补丁源码、二进制来源、Chromium 及第三方通知。其补丁源码延后发布，不能因为仓库有许可证就声称最新二进制可完全重现。

实现阶段明确内核版本、校验值、源码对应关系与支持参数表。按真实内核能力提供指纹功能，不能仅修改 UA 或展示自定义值冒充内核集成。自带密码保存、书签、历史、下载和扩展能力逐项测试；Google 专有服务不属于 Chromium 的必然能力。

依据：[项目说明及发布](https://github.com/adryfish/fingerprint-chromium)、[许可证](https://github.com/adryfish/fingerprint-chromium/blob/main/LICENSE)、[Chromium 项目](https://www.chromium.org/Home/)。

## 全局代理实现约束

Claude Code 官方支持 HTTP/HTTPS 代理与基本认证，不直接支持 SOCKS；使用其原生配置即可，不需修改源码或插件。应用将唯一上游代理转为两端可用入口，SOCKS5 在受管层转换。原生支持代理不代表所有子进程自动遵守，仍需隔离出站限制。

启动时清理相冲突的继承变量，按官方优先级设置受管进程代理；不把真实密码长期写入项目配置。WSL2 内的 127.0.0.1 不应未经验证就视为 Windows 回环入口，需验证具体网络模式；跨边界通道必须鉴权、限制来源并避免 LAN 暴露。不能用 `0.0.0.0` 无认证监听来解决可达性。

同一网关不必然同一出口。浏览器实际网络路径、Code 实际请求及隔离内检测分别验收；日志记录配置版本和检测时间。代理修改停止相关使用、撤销旧结果再重验，故障不能直连。DNS/IPv6/UDP、下载更新和子进程清空代理变量的绕过均须测试。

依据：[Claude Code 网络配置](https://code.claude.com/docs/en/network-config)。

## WSL2 强隔离的实现门槛

官方 Bash sandbox 并非 Code 整进程隔离，文件工具、MCP、hooks 等不全部在其边界内；原生 Windows 不支持该 sandbox。用户明确要求强隔离，因此不能仅设置 `sandbox.enabled` 就完成验收。

设计为专用 WSL2 发行版 + 非特权 Code 用户 + 整进程文件/网络限制。限制宿主盘自动挂载、Windows 互操作及 PATH 继承，只开放选定项目和必要依赖；网络限制覆盖 Code 及所有派生进程，不允许任意直连。评估官方开源 sandbox-runtime 作为组成部分，仍须实测其覆盖面和逃逸边界，不能直接套用默认设置。

WSL 配置是隔离的一部分，不是充分条件：关闭 automount 不阻止具有权限的进程手动挂载；需防提权与挂载权限。`wsl.conf` 按发行版控制，而 `.wslconfig` 会影响所有 WSL2，不能未经说明覆盖用户全局设置。只管理本产品发行版，不用全局 shutdown 影响用户其他任务。

语言和时区从共享配置应用，但 Windows 浏览器与 Linux CLI 平台信息客观不同；Canvas/WebGL 不适用于 Code。禁止“相同完整指纹”“隐藏所有本机信息”等未证明的宣传。

依据：[官方 sandbox 范围](https://code.claude.com/docs/en/sandboxing)、[sandbox-runtime](https://github.com/anthropics/sandbox-runtime)、[Microsoft WSL 配置](https://learn.microsoft.com/en-us/windows/wsl/wsl-config)。以上是实现推导，尚未完成本产品技术验证。

## 安装、登录与持久化

安装采用官方 Code 分发，验证来源和版本；更新通过同一网络策略。WSL2 缺失、虚拟化关闭、管理员确认或重启都有可恢复状态。安装、同步、出口核验和 Code 官方授权是不同阶段。不能安装完成就标为已登录，也不复制浏览器 Cookie 代替授权。

项目目录选择不授予整个宿主文件系统访问。官方授权回调、终端链接和文件选择需要受限宿主桥接，具体机制在 Windows 验证后锁定，不因方便关闭隔离。取消/卸载/恢复不删除用户项目，不改已有 WSL 发行版。

依据：[Claude Code 官方安装](https://code.claude.com/docs/en/setup)。

## 云端与交付

所有依赖安装、类型检查、构建和测试使用 GitHub Actions；本机仅轻量操作。现有 CI 只验证旧前端。后续 Windows 构建、内核验证、WSL2 隔离实测分别建立证据；运行器不支持某项能力就记未验证，不用 Linux UI 测试替代。

ZIP 包含编译程序及说明，仍可能需要 WebView2、WSL2 和内核下载。内核随包或按需安装待确认；资源开销实测，不声称无依赖。后期授权与后台只在两项核心均通过后开始。
