# 前端优先实施方案

## 最新执行顺序

用户已允许进入开发，并明确要求：先设计前端，提供网页预览；用户认可设计风格后再开发后端。本阶段不实现 Go、SQLite、浏览器进程、真实代理或商业授权。

界面接近苹果原生应用的简约体验，遵循渐进展示：默认值做好，主操作清晰，高级选项隐藏。保留 Windows 使用习惯，不添加假的 macOS 窗口控制按钮。

## 本阶段交付

1. React + TypeScript + Vite 前端工程，Tailwind、按需 shadcn 风格组件、Radix 可访问弹窗、Lucide 图标。
2. 使用 imagegen 生成品牌图标，应用到登录、侧栏和网页图标，记录提示词与素材路径。
3. 可随意输入进入的开发登录、注册切换及密码显隐交互。
4. 环境列表、搜索、空状态、创建向导、编辑与删除确认、运行状态演示。
5. 创建向导默认只要求代理地址和环境名称；协议、认证、指纹说明渐进展开。
6. 设置页支持深浅主题、界面中的设置交互；内核和存储的系统操作等待桌面后端接入。
7. 顶部明确提示“界面预览 · 示例数据”，不发起真实网络检测，不保存输入的密码或代理凭据，不上传用户填写内容。
8. GitHub Actions 安装依赖、生成并锁定依赖、类型检查、构建、浏览器交互测试和截图；使用 GitHub Pages 提供网页预览。

## 验收边界

本阶段测试证明前端交互和布局，不证明 Windows 桌面、代理链路、浏览器启动或持久化完成。预览中的运行状态明确为演示；创建流程不得把继续预览描述成真实代理检测成功。

用户浏览网页并确认风格后，再按原需求开发真实核心；核心验收通过后最后开发联网卡密与用户管理面板。

## 原计划待后端阶段收敛的决策

- 固定出口与轮换代理的支持策略。
- 管理窗口退出后环境的处理方式。
- 内核随 ZIP 分发或单独安装。
- 后期授权主体、心跳、重复激活、离线宽限和恢复策略。

这些事项不阻塞当前视觉预览，不因示例交互而被默认为已确定。
