# 前端优先实施方案

版本：V2 · 2026-10-10。当前先按用户要求统一文档。现有多环境预览被否定，新版尚未实现；不得在未重做时声称新界面已发布。

## 开发门槛

文档统一 → 重做前端 → 云端构建/测试/截图 → 网页链接供用户体验 → 用户认可风格 → 后端技术验证与开发。后端包括浏览器、全局代理、WSL2、Code、数据库，不因自动续行跳过用户确认。

## 新版交付内容

1. Claude.ai、Claude Code、Claude 桌面版三个入口；桌面版明确“正在开发中”，不接入功能。
2. 单账号、单一配置，不保留环境表格、搜索、无限新建或批量管理。
3. 一处全局代理设置，两端展示共用状态、实际出口/待检测、修改影响及失败恢复。
4. 浏览器创建与启动流程、环境信息启动页、claude.ai 第二标签页演示；高级设置能查看完整指纹信息和支持状态。
5. 已有浏览器配置时 Code 直接复用；无配置时差异提示，确认后单独创建，未来浏览器复用。
6. WSL2 强隔离安装步骤、同步、出口核验、等待官方授权、终端演示；包括失败重试、取消和等待用户操作，不提供弱隔离回退。
7. 开发登录/注册保留纯前端交互，无真实认证请求；主题、焦点、窄屏和中文可读性完整。
8. 品牌使用 Claude 官方素材，功能图标 Lucide。停用旧生成 logo；素材记录同步。

## 示例与实际业务边界

网页原型中的网络、指纹、安装、终端均明确为示例。不得在预览网站执行官方安装脚本、收集代理秘密、模拟真实 Claude 回答或声称已连接真实沙箱。示例状态只能证明界面行为；进入真实后端阶段后替换为实际事件和检测结果。

无需复制或 iframe 嵌入 Claude.ai 登录页面。普通网页打开官网必须说明是当前浏览器访问，不会自动使用产品代理；不能让用户误以为已完成环境隔离。

## 云端验收范围

- 首次浏览器路径、已有配置安装 Code、Code 单独路径确认、稍后补浏览器共用配置。
- 全局代理无第二份输入，修改旧结果失效；安装失败与禁止弱隔离回退。
- 桌面版占位、高级指纹展开、官方图标、主题、开发登录、键盘和窄屏。
- 截图覆盖首页、启动页、Code 进度/失败、全局连接、指纹详情和深浅主题。

所有依赖安装、类型检查、构建和浏览器测试只在 GitHub Actions。已有 5 项旧预览测试不能算上述新需求通过；新版需更新测试并提供对应提交的结果。

后端与核心两端验收通过后，最后再做卡密和用户管理面板，完整范围见 [开发项目计划](claudeFF开发项目计划.md)。
